# 문 닫은 뒤 — 국경 여관 0.4

[게임 열기](https://kkhkkh20-bit.github.io/after-hours-inn/)

고정 사선 시점의 로우폴리 Godot 게임. main 변경 시 자동 검증 후 Web·Windows를 빌드하고 웹을 갱신한다.

## 이번에 테스트할 상황

직원에게 영업을 맡기고 지하를 파는 동안, 소리가 직원에게 전달돼 확인하러 오게 된다. 작업을 멈추거나 돌아가 설명할 수 있다. 계속 굴착해 확인당하면 기억이 남고 직원이 20초 동안 영업을 거부한다. 범죄 확정·신고·게임오버는 아직 구현하지 않았다.

1. 접수대 가까이 가서 손님에게 1호/2호를 배정한다. H로 직원 고용.
2. 왼쪽 아래 Q 표시로 가서 Q로 지하 이동.
3. 이미 열린 칸의 가장자리로 이동한 뒤 바로 옆 흙벽 클릭. 빠른 굴착은 4초·1닢.
4. 상단 직원 경계와 상태를 확인한다. 소리에 주의하면 직원은 하던 조리·서빙부터 마치고 입구로 접근한다.
5. X로 중단하고 소리가 잦아들길 기다리거나, 입구로 돌아가 Q로 복귀한다. 직원 시야 안 가까이에서 E로 설명할 수 있다. 설명 재사용 간격은 45초이며 확인 기억은 지워지지 않는다.
6. 계속 파는 경우와 R로 조용한 굴착(10초·1닢)을 선택한 경우를 비교한다. 이미 진행 중인 굴착의 방식은 바뀌지 않는다.

V는 직원 시야 표시, M은 소리 켜기/끄기. 벽과 가구가 시야를 가리고, 굴착음은 지하 작업 위치→계단 입구→위층 이동 경로로 감쇠한다. 깊이 파면 소리가 줄지만 돌아오는 시간이 늘어난다. 시야는 100도·4.8m의 시제품 값이다.

시야와 청취 수치는 규칙을 검증하기 위한 표시다. 모든 손님의 지각 AI, 문 개폐, 다층 음향, 숨기기 애니메이션이 완성된 것은 아니다. 효과음은 코드로 만든 간단한 굴착음·직원 발소리·주의 알림이다.

웹에서는 오른쪽 저장/불러오기 버튼을 사용한다. 저장은 브라우저별이며 Windows와 자동 동기화되지 않는다. 기존 0.3 저장을 불러오면 경계 상태를 기본값으로 추가한다.

검증: 시뮬레이션 61개 + 실제 뷰포트/입력 13개. 아래는 기존 0.3 운영 안내이며, 굴착·직원 반응·조작은 위 0.4 안내가 우선한다.

# 문 닫은 뒤 — 국경 여관

전쟁 시기 국경 여관에서 직접 손님을 받고, 직원에게 일을 맡기고, 지하를 확장하는 Godot 4.7.2 시제품입니다. 현재 버전 0.3.

## 브라우저 테스트

[게임 열기](https://kkhkkh20-bit.github.io/after-hours-inn/)

GitHub Pages 배포가 성공하면 위 고정 주소에 최신 main 버전이 반영됩니다. 브라우저는 Edge/Chrome의 WebGL 2 지원 환경을 우선합니다. 웹에서는 저장/불러오기 버튼을 사용하세요. F5는 브라우저 새로고침과 겹칠 수 있습니다. 저장은 같은 브라우저·사이트의 로컬 데이터이며 Windows 저장과 공유되지 않습니다.

## 자동 빌드

main에 변경을 올리면 42개 시뮬레이션 검증과 8개 입력 검증을 실행하고 웹/Windows 빌드를 만듭니다. 성공한 웹 빌드는 GitHub Pages에 배포하고, Windows 빌드는 Actions 실행 페이지의 AfterHours-Windows 아티팩트로 제공합니다.
처음 한 번 Settings → Pages → Build and deployment → Source를 GitHub Actions로 설정해야 합니다. 새 저장소에서 Pages 활성화는 연결 도구로 변경할 수 없는 계정 설정입니다. 배포 단계가 설정 때문에 실패했다면 설정 후 Actions에서 실패 작업을 다시 실행합니다.

# 문 닫은 뒤 — 운영 연결 0.3

Windows ZIP은 압축을 풀고 AfterHours.exe를 실행한다. AfterHours.pck는 같은 폴더에 둔다.
소스는 Godot 4.7.2 Standard에서 project.godot를 Import한 뒤 F5로 실행한다. 편집 화면은 비어 있어도 정상이며 실행할 때 여관이 생성된다.

## 5분 테스트 순서
1. 주인 머리 위 표시를 보고 WASD/방향키로 접수대(책이 놓인 긴 테이블) 앞으로 이동한다.
2. 1 또는 2, 혹은 왼쪽 객실 버튼으로 대기 손님을 배정한다. 방 배정은 접수대 가까이에서만 된다. 숙박비를 한 번 받고 손님이 실제로 걸어간다.
3. 손님이 식사를 주문하면 접수대에서 E를 눌러 3초 준비한다(재료비 1닢). 준비가 끝나면 주인이 자동으로 든다. 주문한 손님에게 접근해 E로 전달하면 4닢을 받는다.
4. 접수대에서 H로 직원을 고용한다(준비금 3닢 / 매일 20시 임금 4닢). 이후 H로 위임을 켜고 끌 수 있다. 직원은 식사 준비와 서빙을 실제 이동으로 수행하고 돌아온다.
5. 바닥에 Q 지하라고 표시된 출입구 가까이에서 Q로 내려간다. 지하에서 WASD로 벽 가까이 가서 바로 옆 흙벽 윗면을 클릭한다. 4초 동안 1칸을 판다(도구비 1닢). 시작 공간은 3×3칸이며 주변으로 확장한다. 입구에서 Q로 복귀한다.
6. 지하 체류 중에도 위층 주문과 시간이 흐른다. H로 직원 위임 여부를 바꾸며 비교한다.
7. 퇴실 후 객실은 청소가 필요하다. 방 안의 빈 공간에 가서 E를 눌러 4초 청소한다.
8. F5로 저장하고 이동/굴착한 뒤 F9로 불러와 진행 상태가 복원되는지 확인한다.

## 공통 조작
Space 정지, Tab 1배/3배속, 마우스 휠 확대/축소, X 작업 취소, G 대기 손님 거절(접수대), Esc 종료.
일시정지 중 시간·이동·작업은 멈춘다. 3배속이면 NPC와 주인의 이동/작업도 빨라진다.

## 비용과 시간
처음 24닢. 게임 1초가 게임 내 6분이며 일시정지/배속에 영향을 받는다. 손님은 약 32초 간격으로 도착하며 대기 2명까지만 받는다. 객실 체류 105초, 입실 후 최대 2번 식사 요청. 대기 65초가 지나면 떠난다.
임금 매일 20시 4닢(고용한 경우), 임대료 다음날 09시부터 매일 12닢, 세금 다음날 12시부터 8닢. 징수원이 오면 접수대 E로 납부한다. 자금 부족 임금/임대료는 미납으로 기록한다.
정상 영업과 위임·굴착이 시간을 놓고 경쟁하는지 확인하기 위한 값이며 고증 또는 최종 밸런스가 아니다.

## 검증과 한계
simulation.gd의 42개 상태/경로/소유/납기/저장 검증, 실제 뷰포트의 버튼/키 입력/굴착 클릭 8개 검증을 포함한다.
Linux에서 실제 3D 화면을 렌더링해 검수했고 Windows로 내보냈다. 새 Windows 빌드 자체의 사용자 PC 확인은 별도다.
완성 캐릭터, 실제 효과음, 기절·끌기, 세력·조사, 직원 휴식과 성향은 아직 없다. docs/CURRENT_STATE.md를 참고한다.
