# 0.8 — 이어지는 2층 복도와 내려다보이는 홀

[게임 실행](https://kkhkkh20-bit.github.io/after-hours-inn/) · [실제 화면과 변경 기록](docs/spatial-v08.md)

1층에서 대상 선택을 해제한 뒤 `2층으로 올라가기`를 누르거나 오른쪽 계단 입구를 탭한다. 주인이 계단까지 걸어가 실제 경사 높이를 따라 올라간다. 2층의 L자 목재 복도에서는 1층 손님과 직원이 계속 보이며 영업도 진행된다. 복도 바닥을 탭해 걷고 `1층으로 내려가기`로 복귀한다. 중앙 홀의 빈 공간은 걸을 수 없다.

지하는 네모 흙 덩어리와 바닥 타일 틈을 없애고, 연속 바닥·외곽 흙벽·목재 지지대로 바꿨다. 실제 벽 면을 탭하면 기존처럼 접근 후 굴착한다. 굴착·저장 데이터의 격자 구조와 비용은 유지한다.

이번 2층은 공간감 검증용 복도다. 객실 두 개와 직원 영업은 아직 1층이고, NPC의 객실 간 계단 이동·난간 너머 AI 시야·도청·발각은 후속 범위다. 지하는 아직 별도 화면으로 전환한다. 기존 Kenney 모델을 재사용했으며 추가 유료 에셋은 없다.

검증: 시뮬레이션 133개 + 실제 포인터/터치 입력 37개 = 170개. 계단 오르내리기, 복도 이동, 홀 가로지르기 방지, 아래층 원격 행동 방지, 2층 저장 복원, 2층에서 깨어난 인물의 계단 탈출, 연속 흙벽 탭 굴착 및 기존 영업·의뢰·조사를 확인했다. 720×1280 실제 Godot 렌더링도 확인했다. 실기기 휴대폰 성능과 터치감은 확인이 남아 있다.

이하 이전 버전 기록이다. 현재 공간 표현과 층 조작은 위 안내가 우선한다.

# 0.7 — 세로 화면 · 클릭/탭 조작

[게임 실행](https://kkhkkh20-bit.github.io/after-hours-inn/) · [변경 기록](docs/mobile-v07.md)

기본 화면은 720×1280 세로형이다. 상단에 시간·돈·정지·배속, 가운데에 여관, 하단에 선택 대상과 행동을 배치했다. 버튼 높이는 논리 좌표 기준 88 이상이며 정보는 영업/관리/의뢰/메뉴 창으로 연다.

## 키보드 없이 플레이

- 바닥 클릭/탭: 해당 지점까지 걸어간다. 흙벽 탭: 작업 위치로 이동해 직접 판다.
- 화면 끌기: 주변을 둘러본다. +/−는 확대/축소, 주인은 주인 위치로 돌아오기다.
- 손님 탭: 대상 선택. 하단의 다가가기·제압·끌기·석방 등이 대상 상태에 맞게 바뀐다.
- 영업: 방 배정, 손님 거절, 식사 준비/집기, 객실 청소, 징수원 세금 납부. 필요한 장소까지 걸어가 처리한다.
- 식사를 들면 하단에 주문 손님에게 전달 버튼이 나온다. 대상 손님까지 이동해 전달한다.
- 관리: 직원 고용/위임, 도구 수리, 직원에게 설명하기. 지하에서는 구금칸을 먼저 설치할 수도 있다.
- 의뢰: 수락·보수·거절·보호, 경비 조사 허용과 뇌물 대응.
- 메뉴: 저장·불러오기, 소리, 직원 시야 표시, 선택 해제.
- 하단 층 이동 버튼: 입구까지 걸어가 위층/지하 이동. 중단 버튼: 이동/작업 취소.
- 지하에서 대상 선택을 해제하면 하단에 가까운 벽 파기와 곡괭이/삽 전환이 나온다.

터치와 자동 생성 마우스 입력을 중복 처리하지 않는다. 정보창에서 시작한 터치는 창을 닫은 뒤 뒤쪽 바닥을 누르지 않도록 입력을 잡아 둔다. 화면을 끈 동작은 이동 명령이 되지 않는다.

검증: 기존 시뮬레이션 120개 + 세로 화면/포인터/터치 입력 30개 = 150개. 입력 검증은 키보드를 사용하지 않고 실제 버튼과 월드 입력을 보낸다. 정상 영업·서빙·고용과 의뢰→제압→운반→층 이동→설치/구금→굴착→보수→저장 복원을 확인했다. 720×1280 실제 Godot 화면도 렌더링했다.

실제 Android/iPhone 브라우저의 터치감·주소창·안전 영역·성능은 실기기 확인이 남아 있다. Web 저장은 브라우저별이며 기존 저장을 이어서 읽는다.

이하 0.6 이전 기록의 단축키 중심 안내는 과거 설명이다. 현재 기본 조작은 위 버튼·탭 안내를 따른다.

# 0.6 — 지하 진입·직접 굴착과 넓은 테스트 맵

[게임 실행](https://kkhkkh20-bit.github.io/after-hours-inn/)

- 화면 위쪽 `지하 입구 열고 내려가기 [Q]` 클릭: 주인이 입구까지 실제로 걸어가 뚜껑을 열고 내려간다. Q도 같은 동작이다. 지하에서는 입구로 걸어가 위층으로 복귀한다.
- 지하의 흙벽 클릭: 파기 가능한 옆칸까지 직접 걸어간 뒤 곡괭이질한다. 먼저 정확히 벽 옆에 붙을 필요가 없다. 클릭 순간의 좌표로 선택한다.
- E 또는 `가까운 흙벽 파기` 버튼: 가장 가까운 벽을 선택해 이동·굴착한다.
- 곡괭이·삽은 기본 지급. R로 빠른 곡괭이 4초 / 조용한 삽 10초 전환. 손에 든 도구의 움직임과 진행률 표시. 도구 내구도 24, 작업당 1 사용, 접수대 T 수리 2닢. 굴착 비용은 기존처럼 1닢이다.
- 이동 중 WASD 또는 X로 취소할 수 있다. 도착 전에는 비용과 내구도를 쓰지 않는다. 파기 시작한 후 중단하면 이미 쓴 비용은 돌아오지 않는다.
- 실내 바닥 14×8 → 20×12, 지상 이동 범위 28×16. 중앙 통로의 가구를 옮기고 전면에 열린 출입구를 뒀다. 마당을 걸을 수 있고 카메라가 주인을 따라간다.
- 지하 시작 공간 3×3 → 5×5. 기존 저장도 시작 공간을 넓혀 읽으며, 이미 판 통로·구금칸·의뢰는 유지한다. I로 양옆 정보 패널을 접어 시야를 넓힐 수 있다.

시뮬레이션 120개 + 실제 입력 27개 = 147개 검증. 출입 버튼, 마우스 이동 없는 흙벽 클릭, 자동 접근 후 굴착, E 굴착, T 수리를 실제 입력 경로로 확인했다.

아래는 이전 0.5 이하 기록이다. 현재 진입·굴착·맵 크기는 위 0.6 안내가 우선한다.

# 문 닫은 뒤 — 0.5 비밀 의뢰와 조사

[게임 실행](https://kkhkkh20-bit.github.io/after-hours-inn/) · [제작 기록](docs/operations-v05.md)

이번 버전은 접수·식사·직원·굴착 위에 손님 선택, 2초 제압, 기절/회복, 끌기, 계단 동반 이동, 자유 위치의 구금칸, 유지비/탈출, 의뢰 분기, 목격/신고, 실제 경비 방문/수색을 연결한다. 기존 세금 징수원과 신고를 받고 오는 경비는 별개다.

## 한 판 테스트 순서

1. 손님에게 방을 배정하고 H로 직원을 고용한다. 정상 영업은 계속 돌아간다.
2. 접수대에서 J로 비밀 의뢰를 받는다. 손님을 클릭해 대상을 선택할 수 있으며, 선택하지 않으면 현재 손님 한 명이 지정된다. 180초 안에 그 대상을 지하에 30초 억류하면 보수 24닢. K는 수락 전 거절, 수락 후에는 아직 위해를 가하지 않은 손님 보호와 감사금 8닢 분기다.
3. 먼저 지하를 확장해 입구에서 두 칸 이상 떨어진 열린 칸 위에서 B로 구금칸을 만든다. 설치 8닢, 실제 구금 중 30초마다 유지비 1닢. 구금칸은 한 곳·한 명이다. 더 깊이 파면 동선이 길어진다.
4. 위층으로 돌아와 대상 클릭 → 가까이서 Z로 2초 제압 → C로 끌기. 이동 속도가 줄고 Q로 함께 지하에 내려간다. 대상은 45초 뒤 회복하므로 이동을 미루면 도망친다. 음식과 사람을 동시에 운반할 수 없다.
5. 구금칸 곁에서 B로 구금한다. 30초 조건을 채운 뒤 접수대에서 J로 보수를 받는다. 보수를 받아도 구금자는 남는다. C로 풀어주면 출구로 도망쳐 신고하려 한다. 유지비가 없을 때도 탈출한다.
6. 손님은 방향·벽·층에 따라 목격하고 실제 출구로 나간 뒤 신고한다. 직원도 하던 주문을 마친 뒤 문으로 가 경비를 부른다. 기절한 사람을 숨기지 않고 방치해도 발견될 수 있다.
7. 신고 15초 뒤 경비가 와 접수대에서 기다린다. 접수대 E는 입구 주변 조사 허용, O는 뇌물 12닢. 신고가 둘 이상이면 뇌물을 거절한다. 응답하지 않아도 20초 뒤 제한 수색에 들어간다. 발견되면 20닢 벌금과 구금 해제. 돈이 부족하면 기존 미납 장부에 남는다.

## 조작

WASD 이동, 손님 클릭 선택, E 일반 상호작용/조사 허용, 1/2 객실 배정, G 손님 거절, H 직원 고용/위임, Q 계단, Z 제압, C 끌기/내려놓기/석방, B 구금칸 설치/구금, J 의뢰 수락/보수, K 의뢰 거절/손님 보호, O 경비 뇌물.

R 빠른/조용한 굴착, X 작업 중단, V 직원 시야 표시, M 소리 전환, Space 정지, Tab 배속, 휠 확대. Web 저장/불러오기는 오른쪽 버튼을 사용한다.

시뮬레이션 107개 + 실제 뷰포트/입력 20개 = 127개 검증. 기존 0.3/0.4 저장 파일에 새 인물·의뢰·조사 상태 기본값을 추가한다. 운반 중인 사람, 구금칸, 의뢰 보수, 조사 진행도 모두 저장한다. 웹 저장은 브라우저별이며 Windows와 자동 동기화되지 않는다.

## 이번 범위

구금 의뢰 한 건의 분기와 경비 한 종류의 제한 수색이다. 실제 세력 거점 임대, 자유 건축 전체, 전투/무기/사망/시신, 음식 효과, 완성된 인물 애니메이션과 역사 고증은 후속 범위다. 기절은 이 시제품의 추상적 상태이며 제압은 2초 행동으로 표현한다. 경계/청취 수치는 검증용 UI다.

이하 이전 0.4/0.3 기록은 과거 기능 설명이다. 현재 동작은 위 0.5 설명이 우선한다.

# 문 닫은 뒤 — 국경 여관 0.4

[게임 열기](https://kkhkkh20-bit.github.io/after-hours-inn/)

고정 사선 시점의 로우폴리 Godot 게임. main 변경 시 자동 검증 후 Web·Windows를 빌드하고 웹을 갱신한다.

## 이번에 테스트할 상황

직원에게 영업을 맡기고 지하를 파는 동안, 소리가 직원에게 전달돼 확인하러 오게 된다. 작업을 멈추거나 돌아가 설명할 수 있다. 계속 굴착해 확인당하면 기억이 남고 직원이 20초 동안 영업을 거부한다. 범죄 확정·신고·게임오버는 아직 구현하지 않았다.

1. 접수대 가까이 가서 손님에게 1호/2호를 배정한다. H로 직원 고용.
2. 왼쪽 아래 Q 표시로 가서 Q로 지하 이동.
3. 이미 열린 칸의 가장자리로 이동한 뒤 바로 옆 흙벽 클릭. 빠른 굴착은 4초·1닢.
4. 상단 직원 경계와 상태를 확인한다. 소리에 주의하면 직원은 하던 조리·서빙부터 마치고 입구로 접근한다.
5. X로 중단하고 소리가 잦아들길 기다리거나, 입구로 돌아가 Q로 복귀한다. 직원 시야 안 가까이에서 E로 설명할 수 있다. 설명 재사용 간격은 45초이며 확인 기억은 지워지지 않는다.
6. 계속 파는 경우와 R로 조용한 굴착(10초·1닢)을 선택한 경우를 비교한다. 이미 진행 중인 굴착의 방식은 바뀌지 않는다.

V는 직원 시야 표시, M은 소리 켜기/끄기. 벽과 가구가 시야를 가리고, 굴착음은 지하 작업 위치→계단 입구→위층 이동 경로로 감쇠한다. 깊이 파면 소리가 줄지만 돌아오는 시간이 늘어난다. 시야는 100도·4.8m의 시제품 값이다.

시야와 청취 수치는 규칙을 검증하기 위한 표시다. 모든 손님의 지각 AI, 문 개폐, 다층 음향, 숨기기 애니메이션이 완성된 것은 아니다. 효과음은 코드로 만든 간단한 굴착음·직원 발소리·주의 알림이다.

웹에서는 오른쪽 저장/불러오기 버튼을 사용한다. 저장은 브라우저별이며 Windows와 자동 동기화되지 않는다. 기존 0.3 저장을 불러오면 경계 상태를 기본값으로 추가한다.

검증: 시뮬레이션 61개 + 실제 뷰포트/입력 13개. 아래는 기존 0.3 운영 안내이며, 굴착·직원 반응·조작은 위 0.4 안내가 우선한다.

# 문 닫은 뒤 — 국경 여관

전쟁 시기 국경 여관에서 직접 손님을 받고, 직원에게 일을 맡기고, 지하를 확장하는 Godot 4.7.2 시제품입니다. 현재 버전 0.3.

## 자동 빌드

main에 변경을 올리면 42개 시뮬레이션 검증과 8개 입력 검증을 실행하고 웹/Windows 빌드를 만듭니다. 성공한 웹 빌드는 GitHub Pages에 배포하고, Windows 빌드는 Actions 실행 페이지의 AfterHours-Windows 아티팩트로 제공합니다.
처음 한 번 Settings → Pages → Build and deployment → Source를 GitHub Actions로 설정해야 합니다. 새 저장소에서 Pages 활성화는 연결 도구로 변경할 수 없는 계정 설정입니다. 배포 단계가 설정 때문에 실패했다면 설정 후 Actions에서 실패 작업을 다시 실행합니다.

# 문 닫은 뒤 — 운영 연결 0.3

Windows ZIP은 압축을 풀고 AfterHours.exe를 실행한다. AfterHours.pck는 같은 폴더에 둔다.
소스는 Godot 4.7.2 Standard에서 project.godot를 Import한 뒤 F5로 실행한다. 편집 화면은 비어 있어도 정상이며 실행할 때 여관이 생성된다.

## 5분 테스트 순서
1. 주인 머리 위 표시를 보고 WASD/방향키로 접수대(책이 놓인 긴 테이블) 앞으로 이동한다.
2. 1 또는 2, 혹은 왼쪽 객실 버튼으로 대기 손님을 배정한다. 방 배정은 접수대 가까이에서만 된다. 숙박비를 한 번 받고 손님이 실제로 걸어간다.
3. 손님이 식사를 주문하면 접수대에서 E를 눌러 3초 준비한다(재료비 1닢). 준비가 끝나면 주인이 자동으로 든다. 주문한 손님에게 접근해 E로 전달하면 4닢을 받는다.
4. 접수대에서 H로 직원을 고용한다(준비금 3닢 / 매일 20시 임금 4닢). 이후 H로 위임을 켜고 끌 수 있다. 직원은 식사 준비와 서빙을 실제 이동으로 수행하고 돌아온다.
5. 바닥에 Q 지하라고 표시된 출입구 가까이에서 Q로 내려간다. 지하에서 WASD로 벽 가까이 가서 바로 옆 흙벽 윗면을 클릭한다. 4초 동안 1칸을 판다(도구비 1닢). 시작 공간은 3×3칸이며 주변으로 확장한다. 입구에서 Q로 복귀한다.
6. 지하 체류 중에도 위층 주문과 시간이 흐른다. H로 직원 위임 여부를 바꾸며 비교한다.
7. 퇴실 후 객실은 청소가 필요하다. 방 안의 빈 공간에 가서 E를 눌러 4초 청소한다.
8. F5로 저장하고 이동/굴착한 뒤 F9로 불러와 진행 상태가 복원되는지 확인한다.

## 공통 조작
Space 정지, Tab 1배/3배속, 마우스 휠 확대/축소, X 작업 취소, G 대기 손님 거절(접수대), Esc 종료.
일시정지 중 시간·이동·작업은 멈춘다. 3배속이면 NPC와 주인의 이동/작업도 빨라진다.

## 비용과 시간
처음 24닢. 게임 1초가 게임 내 6분이며 일시정지/배속에 영향을 받는다. 손님은 약 32초 간격으로 도착하며 대기 2명까지만 받는다. 객실 체류 105초, 입실 후 최대 2번 식사 요청. 대기 65초가 지나면 떠난다.
임금 매일 20시 4닢(고용한 경우), 임대료 다음날 09시부터 매일 12닢, 세금 다음날 12시부터 8닢. 징수원이 오면 접수대 E로 납부한다. 자금 부족 임금/임대료는 미납으로 기록한다.
정상 영업과 위임·굴착이 시간을 놓고 경쟁하는지 확인하기 위한 값이며 고증 또는 최종 밸런스가 아니다.

## 검증과 한계
simulation.gd의 42개 상태/경로/소유/납기/저장 검증, 실제 뷰포트의 버튼/키 입력/굴착 클릭 8개 검증을 포함한다.
Linux에서 실제 3D 화면을 렌더링해 검수했고 Windows로 내보냈다. 새 Windows 빌드 자체의 사용자 PC 확인은 별도다.
완성 캐릭터, 실제 효과음, 기절·끌기, 세력·조사, 직원 휴식과 성향은 아직 없다. docs/CURRENT_STATE.md를 참고한다.
