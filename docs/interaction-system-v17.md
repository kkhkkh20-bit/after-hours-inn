# 3D 여관 운영·입력 시스템 상세 기획 v1.7

작성: 2026-10-17. 기준: 기존 3D. 마지막 탑다운 실험판은 기본 개발 대상으로 사용하지 않는다.
목표는 클릭 의도와 실제 결과를 일치시키고, 같은 접객을 반복해도 사람·방·작업이 꼬이지 않도록 만드는 것이다. 그림 교체와 신규 범죄 콘텐츠보다 이 규칙을 우선한다.

## 1. 레퍼런스에서 확인한 사실과 적용 범위

### Stardew Valley 모바일: 대상 탭 → 접근 → 상호작용
출처: https://stardewvalleywiki.com/Mobile_Controls
모바일 기본 방식에 바닥 탭 이동, 대상 탭 시 접근·상호작용, 대상에 맞춘 도구 자동 선택이 있다. 문서 자체도 이동 중 장애물·움직이는 NPC와의 상호작용 오류를 설명한다. 이를 버그 없는 시스템이라는 근거로 사용하지 않는다.
우리 적용: 바닥 한 번으로 이동, 사람 선택 시 올바른 대상 고정, 실제 행동을 고르면 접근과 수행을 자동 연결. 원작의 전투·선물·도구 단축바는 가져오지 않는다.

### Tavern Master: 직원 역할·공간 배치·자동 운영
출처: https://untitledstudio.dev/games/tavern-master
개발사는 식탁·벤치·주방·위층 객실, 웨이터·조리사·청소부, 배치에 따른 대기와 자동 운영을 설명한다.
우리 적용: 일반 접객은 직원에게 맡길 수 있고, 플레이어는 숙박 배정·확장·특수 손님에 개입한다. 직원 업무와 예약·수금은 게임 상태에서 관리한다. 특정 버튼 위치·클릭 횟수가 원작과 동일하다고 주장하지 않는다.

### Travellers Rest: 접수와 식음 서비스의 분리
출처: https://www.isolatedgames.com/travellers-rest/
개발사 소개는 직접 접객, 가구로 여관 확장, 메뉴·제품 준비를 설명한다.
보조 공식 기록: https://steamcommunity.com/games/1139980/announcements/detail/6583755500549185297
2023년 Drinks & Staff 업데이트는 별도 접수대와 하우스키퍼의 객실 배정을 소개했다. 이는 당시 기능 설명이지 현 버전 전체 조작 검증은 아니다.
우리 적용: 숙박 문의가 식당 통로를 막지 않게 접수점을 분리하고 안내·청소 위임을 지원한다. 사용자의 선택에 따라 식사는 공용 식당에서 하도록 한다. 원작의 룸서비스는 그대로 가져오지 않는다.

### Godot: 입력 전달과 길찾기
출처: https://docs.godotengine.org/en/stable/tutorials/inputs/inputevent.html
GUI가 처리한 입력이 세계 조작으로 다시 실행되지 않도록 엔진의 입력 전달 규칙을 따른다.
출처: https://docs.godotengine.org/en/stable/classes/class_astargrid2d.html
현재 맵은 층별 평면과 굴착 격자이므로 Godot AStarGrid2D를 유지하고 목적지·접근점·실패 처리를 정리한다. 이번 개편에서 NavigationAgent3D나 LimboAI를 도입했다고 표시하지 않는다. 내비게이션 메시와 플러그인 추가는 별도 호환·연결 작업이 필요하며 그 자체가 예약·작업 버그를 해결하지 않는다.

## 2. 이번 구현 범위와 뒤로 미룰 범위

이번에 적용할 것: R01 입력 분리, R02 대상 판정, R03 선택창, R04 이동 명령, R05 대화, R06 객실 예약, R07 식사 작업, R08 손님 도착, R09 화면 조작, R10 안내·상태 표시, R11 저장 시 정합성, R12 확인 가능한 구현 기록.
유지할 것: 기존 3D와 지하·시설·비밀 길·직원 기능. 새 입력 규칙에 연결한다.
후속 운영 확장: 2·4인 실제 일행, 기본 2인실·4인실, 넓은 공용 식당에서 숙박객 식사, 자유 지하 도시. 이들은 기존 요구이며 이번 입력 개편만으로 완료했다고 표시하지 않는다.
기존 5개 객실은 이번에도 반복 판매·퇴실·청소를 보장하는 대상으로 삼는다.

## 3. 입력 계약 R01

기준 화면 720×1280 세로. 아래 수치는 원작 수치가 아니라 우리 게임의 설계값이다.
- 마우스와 터치는 하나의 포인터 처리기로 들어간다. 터치에서 합성된 마우스 입력은 중복 실행하지 않는다.
- 누른 순간 후보 대상을 기록하고, 손을 뗐을 때 클릭을 확정한다. 이동 중인 손님도 처음 누른 손님을 유지한다.
- 누른 위치에서 18 논리 픽셀 이상 움직이면 드래그다. 드래그 종료는 이동·대화·굴착을 실행하지 않는다.
- 두 손가락은 확대·축소 전용이다. 어느 손가락을 먼저 떼더라도 남은 손가락으로 클릭이 발생하지 않는다.
- UI 위에서 시작한 제스처는 끝까지 UI 소유다. 창 밖으로 끌어도 카메라가 움직이지 않는다.
- 버튼을 눌러 창이 닫혀도 같은 입력으로 바닥 이동을 실행하지 않는다.
- 선택창 밖 빈 곳 첫 클릭은 창 닫기만 한다. 닫는 동시에 뒤의 바닥 명령을 실행하지 않는다.
- 다른 사람을 누르면 기존 창을 닫고 그 사람의 창을 연다. 대상 변경 자체로 기존 이동·조리 작업을 취소하지 않는다.

## 4. 대상 판정 R02

우선순위: 모달 UI → 열린 선택창 → 명시적으로 켠 건설 모드 → 인물의 몸체 직접 명중 → 인물 확장 영역 → 시설·객실 → 이동 가능한 바닥.
- 일반 클릭으로 건설 모드에 들어가지 않는다. 기존 바닥 연속 탭으로 입구 공사 메뉴가 열리는 기능은 제거한다.
- 인물 클릭은 발과 머리의 투영 위치를 잇는 몸체 영역으로 계산한다. 고정된 한 점 주변의 원만 사용하지 않는다.
- 최소 인물 터치 폭은 88 논리 픽셀(화면이 360 CSS 픽셀 폭이면 약 44 CSS 픽셀). 실제 몸체를 누른 후보가 확장 영역 후보보다 우선한다.
- 확장 영역에 여러 인물이 겹치면 가까운 한 사람을 임의로 실행하지 않는다. 이름·상태를 보여주는 대상 선택창에서 고르게 한다.
- 몸체가 겹치면 직접 명중 거리와 카메라에서의 깊이를 함께 사용한다. 현재 표시하지 않는 층의 사람은 후보에서 제외한다.
- 사람과 접수대가 겹쳐 보이면 사람의 직접 명중이 우선한다. 접수대는 별도 표시된 표식과 가구 영역으로 선택한다.
- 객실 선택은 현재 표시 층의 객실 표식·침대 주변에서 한다. 방 안의 일반 바닥은 이동을 유지한다. 방 전체를 선택 영역으로 삼으면 이동 클릭을 가로채므로 이 방식으로 구체화했다. 숨긴 방이나 화면 밖 지하 시설이 지상의 클릭을 가로채지 않는다.

## 5. 선택창 R03

선택창은 대상 가까이에 열되 열릴 때 화면 위치를 고정한다. 손님이 걸어도 버튼이 손가락 아래에서 도망가지 않는다.
- 기본 폭 320~360 논리 픽셀. 가용 화면의 70%를 넘기지 않는다.
- 버튼 높이 88, 간격 8. 제목·요구·선택지는 각각 별도 줄이다.
- 한 화면에 기본 행동 최대 4개. 위험·관리·상세 행동은 하위 창으로 분리한다.
- 선택지는 위쪽부터 지금 가능한 기본 행동, 보조 행동, 다른 조치 순서다. 퇴장·살해 같은 위험 행동은 기본 접객의 첫 버튼이 될 수 없다.
- 방 배정은 별도 방 선택 화면으로 전환한다. 각 행에 방 번호·층·빈방/사용 중/청소 필요·요금을 쓴다.
- 사용 중·예약 중인 방은 선택 불가다. 청소 필요 방을 누르면 청소 후 안내할지 명확히 처리하며 조용히 실패하지 않는다.
- 목록이 길면 창 안에서 스크롤한다. 창 전체를 화면 바깥으로 밀어내지 않는다.
- 제목 오른쪽 닫기 버튼, 바깥 탭 닫기를 제공한다. 이동·공사·주문 취소는 별도 현재 작업 표시에서 제공한다.
- 대화·방 선택 중에는 시간을 임시 정지한다. 닫을 때 사용자가 원래 멈춰둔 상태를 보존한다.
- 대상이 떠나거나 사망하거나 상태가 바뀌면 실행 직전에 다시 확인한다. 잘못된 대상에 동작하지 않고 이유를 표시한다.

## 6. 이동과 작업 R04

하나의 주인에게 활성 명령은 하나다. 선택만으로 활성 명령을 취소하지 않는다.
명령 상태: 요청 → 유효성 확인 → 경로 이동 → 수행 → 완료. 실패와 취소는 별도 종료 상태다.
- 바닥 이동은 현재 이동·예약 대기·대화 접근 명령을 명시적으로 대체한다. 미완성 작업에 묶인 예약과 식사는 각 취소 규칙으로 정리한다.
- 손님 행동을 고르면 손님 몸속이 아니라 주변의 도달 가능한 접근점을 찾는다. 여러 접근점을 비교해 갈 수 있는 짧은 경로를 고른다.
- 이동한 손님은 일정 간격으로 경로를 갱신한다. 무한 추적하지 않는다. 15초 안에 접근하지 못하면 실패 안내와 함께 종료한다.
- 목적지 주변 1.25m 내 접근점이 없으면 명령을 시작하지 않는다. 맵의 먼 임의 지점으로 자동 이동시키지 않는다.
- 이동 중 지나갈 수 없는 경로는 실패 처리한다. 빈 경로를 도착 성공으로 간주하지 않는다.
- 문·가구 모서리를 대각선으로 자르지 않는다. 격자의 실제 막힘과 시각적 가구 위치를 일치시킨다.
- 이동 목적지는 작은 원과 경로로 표시한다. 완료·취소 시 표시를 지운다. 실패한 위치는 짧게 붉게 표시한다.
- 층 전환은 계단·입구 행동으로 요청한다. 위층 바닥이 투영되어 겹친다는 이유만으로 지상 이동이 위층 이동으로 바뀌지 않는다.

## 7. 손님과 대화 R05·R08

일반 숙박객: 입장 → 문의 자리 이동 → 문의 → 객실 안내 → 사용 → 퇴실 → 출구 이동 → 퇴장.
식사객: 입장 → 식당 빈자리 이동 → 주문 → 준비 대기 → 식사 → 결제·퇴장.
- 기본 인물 선택창은 이름과 짧은 요구를 먼저 보여준다. 더 듣기와 배정·식사 처리를 구분하되 같은 요구를 두 번 확인하게 하지 않는다.
- 일반 손님은 처음부터 협박·극단적인 비밀 대사만 하지 않는다. 숙박·식사 요청이 먼저다. 위험한 인물의 태도는 개별 상황으로 구분한다.
- 만실인데 숙박객을 계속 생성하지 않는다. 빈방·청소 중 방·현재 문의 손님 수로 도착을 제한한다.
- 기존 문의 손님은 2명까지. 방이 없으면 식사만 권하거나 정중히 돌려보낼 수 있다. 손님 과잉 자체로 실패시키지 않는다.
- 일반 손님을 클릭했다고 공사·주문이 취소되거나 손님이 다른 층으로 이동하지 않는다.

## 8. 객실 예약과 돈 R06

객실 상태: 빈방 → 예약 → 사용 중 → 청소 필요 → 청소 중 → 빈방.
- 방의 점유자는 하나, 예약자는 하나다. 두 손님에게 같은 방을 중복 배정할 수 없다.
- 배정 클릭 순간 유효성 확인 후 예약한다. 주인이나 직원이 접근하는 동안 다른 배정이 끼어들지 않는다.
- 청소 후 안내도 먼저 예약한다. 다른 직원이 그 방을 다시 판매할 수 없다.
- 예약 후 손님이 떠나거나 작업을 취소하면 예약을 해제한다. 이전에 사용하던 방을 옮길 때는 새 방 예약 성공 뒤에 기존 방을 비운다.
- 숙박비는 입실 확정 때 한 번만 받는다. 같은 버튼 연타·대화 재개·저장 복원으로 중복 수금하지 않는다.
- 퇴실은 해당 방에 등록된 손님과 실제 퇴실자가 일치할 때만 방을 비운다.
- 청소 완료는 방이 비었을 때만 적용한다. 이전 청소 작업이 새 투숙객의 방 상태를 덮어쓰지 않는다.

## 9. 주문과 직원 R07

주문 상태: 대기 → 조리 담당 확정 → 조리 → 준비 완료 → 운반 → 제공 완료. 취소는 별도 상태다.
- 주문마다 담당자는 한 명이다. 주인과 직원이 동시에 같은 주문을 가져가지 않는다.
- 주인이 이미 직원 담당 주문을 선택하면 '직원이 준비 중'을 표시한다. 조용히 실패하거나 두 번째 음식을 만들지 않는다.
- 주문 처리 선택 한 번으로 주방 접근·조리·집기·손님 접근·제공을 이어간다.
- 제공 직전에 손님·주문·운반자가 여전히 유효한지 확인한다. 수입과 제공 횟수는 한 번만 반영한다.
- 취소된 조리는 상태와 담당을 되돌린다. 이미 완성된 음식은 운반/준비 상태에 맞게 남긴다.
- 직원 자동화는 새 일반 업무만 맡는다. 플레이어가 잡은 주문이나 예약을 빼앗지 않는다.
- 직원 고용은 역할·고용비·일당을 같은 창에서 확인하고 한 번에 처리한다.

## 10. 화면 R09·안내 R10

- 첫 실행은 1층 식당과 마당을 중심으로 한다. 주인을 계속 따라가며 카메라가 흔들리지 않는다.
- 상단에는 돈·시간과 정지·배속·층 보기·설정만 둔다. 하단 고정 행동판은 만들지 않는다.
- 층 보기는 식당/객실/지하/전체를 명확히 구분한다. 보기 전환은 주인의 실제 층을 바꾸지 않는다.
- 전체 보기에서는 작은 대상을 강제로 누르기보다 선택 후 확대할 수 있다. 기본 운영 화면은 전체 건물을 너무 작게 축소하지 않는다.
- 지하 선택 시 지상 상태는 상단 요약으로 유지한다. 지상 실시간 보조 화면은 이번 핵심 입력 개편 이후의 별도 표시 작업으로 남긴다.
- 주인의 현재 행동과 취소 버튼을 작게 표시한다. 실패 이유와 수금 결과는 짧은 알림으로 보여준다.
- UI의 상태 조회 함수는 게임 상태를 변경하지 않는다. 화면을 열거나 새로 그린 횟수로 조사·손님·예약이 바뀌면 안 된다.

## 11. 저장과 정합성 R11

기존 저장은 호환을 유지한다. 새로운 예약·담당 필드에는 기본값을 추가한다.
- 불러올 때 존재하지 않는 손님에 연결된 예약을 해제한다.
- 실제 점유 중인 방에 걸린 별도 예약은 정리한다.
- 숨겨진 선택창, 이전 포인터 누름, 대기 중 대화 콜백은 불러오기와 새 게임에서 초기화한다.
- 저장 파일 검증이 실패하면 현재 진행을 덮어쓰지 않는다.

## 12. 구현과 확인 기준 R12

계획·코드 반영·실행 확인을 구분해 기록한다. 빌드 성공만으로 '버그 없음'이라고 보고하지 않는다.
이번에 필요한 집중 확인: 클릭 한 번=명령 한 번, 드래그 후 이동 없음, UI 닫기 후 바닥 명령 없음, 움직이는 손님 선택 유지, 겹친 대상 구분, 같은 방 중복 예약 방지, 청소 후 재판매, 이동 취소 시 예약 해제, 다른 층 대상 명령 안전 처리, 기존 저장 읽기.
전체 콘텐츠 검수나 대규모 회귀 검사 대신 이번 변경 경로만 확인한다. 확인하지 않은 모바일 실기기 조작감·사람 간 자연스러운 회피·전체 게임 밸런스를 완료로 표시하지 않는다.

## 13. 파일별 구현 책임

- scripts/inn_pointer.gd: 마우스·터치·드래그·핀치 분류.
- scripts/inn_selection.gd: 인물·시설 후보 판정과 겹침 후보 반환.
- scripts/object_context.gd: 고정 위치 선택창, 스크롤, 기본/상세 행동, 현재 작업 표시.
- scripts/inn_commands.gd: 명령 취소·대화 접근·유효성 확인·시간 제한.
- scripts/inn_tycoon.gd: 예약·점유·청소 상태와 부작용 없는 화면 정보.
- scripts/inn_dialogue.gd: 짧은 요구·배정·식사·일반 손님 태도.
- scripts/simulation.gd: 실제 이동·조리·수금의 단일 실행 경로.
- scripts/main.gd: 입력과 표시 연결. 별도의 접객 상태를 중복 소유하지 않는다.

## 14. 반영 기록

상세 기획을 작성한 뒤 기존 3D를 변경했다. 탑다운 실험판을 기본으로 삼지 않았다.
- R01~R03: 독립 포인터 처리·인물 후보 판정·고정 선택창·상단 닫기·스크롤·88 논리 픽셀 버튼을 반영했다. 실제 화면에 표시하지 않는 층은 인물 선택에서 제외한다.
- R04: 선택 시 작업 자동 취소를 제거했다. 바닥 이동은 명시적 대체 명령이며, 목적지 주변 유효 접근점·15초 접근 제한·경로 표시를 추가했다. 전체 보기에서 위층 투영 바닥이 지상 클릭을 가로채는 자동 층 전환을 제거했다.
- R05~R08: 일반 손님의 첫 요청을 짧은 숙박·식사 요구로 정리했다. 문의 손님을 최대 2명으로 제한하고 실제 도달 가능한 접수·식당 위치를 고른다. 수용 불가능하면 추가 숙박객을 무한 생성하지 않는다.
- R06: 예약자를 추가해 안내 전 방을 확보한다. 청소 후 안내, 중복 수금 방지, 방 이동 실패 시 기존 방 보존, 취소 시 예약 해제를 구현했다.
- R07: 주인이 맡은 주문을 직원이 다시 가져가지 않게 했다. 취소 시 대기·준비 주문의 담당을 해제하고, 떠난 손님의 음식을 들고 직원이 영구 정지하지 않게 처리했다.
- R09~R10: 기본은 식당·마당 보기, 객실·지하·전체 보기와 정지·배속은 상단에 둔다. 현재 작업·취소와 지하의 지상 영업 수치 요약을 표시한다. 화면 정보 조회의 실종 신고 부작용을 제거했다.
- R11: JSON을 다시 읽을 때 예약 방 번호를 정수로 정규화하고 고아 예약을 해제한다. 기본 저장 구조가 잘못되면 현재 진행을 덮어쓰지 않는다.

집중 확인 결과: 25/25 조건 통과. 실제 Godot GUI에 마우스 누름·뗌을 전달해 요구→방 선택→예약을 확인했고, 예약 중복·중복 결제·청소 후 재판매·취소·도달 불가 이동·포인터 대상 유지·드래그·UI 소유·핀치·선택창 위치·저장 복원을 확인했다. 기록: interaction-v17-checks.txt. 전체 기존 회귀 검사와 완주 리뷰는 실행하지 않았다.

확인 한계: Android/iPhone 실기기 터치, 장시간 대규모 손님 회전, 사람끼리의 자연스러운 회피, 전체 범죄·세력 콘텐츠와 최종 밸런스는 완료로 주장하지 않는다. 후속 운영 확장 항목도 이번 반영 범위와 구분한다.

추가 동선 수정: 1층 객실은 공용 복도와 분리했다. 2층으로 가는 손님의 경로가 1층 2호실 내부를 통과하지 않음을 실제 맵의 길찾기 결과로 확인했다. 대화 중 상단 재개 버튼도 표시와 실제 재개 상태가 일치하도록 보완했다.
