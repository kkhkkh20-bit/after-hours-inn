# 0.5 — 운영과 비밀 의뢰를 연결한 통합 시제품

## 결과
동일한 손님 엔티티에 기절·회복·운반·구금·탈출·신고 상태를 연결했다. 이동/층 변경/저장 시 운반 소유권이 유지되고 식사와 중복 소유하지 않는다. 구금칸을 실제 열린 지하의 원하는 위치에 설치한다. 한 칸·한 명이 현재 상한이다.

의뢰 수락→손님 선택→제압→운반→구금 30초→접수대 정산을 연결했다. 거절·손님 보호·시간 초과·대상 탈출의 분기도 있다. 보수 지급은 한 번이고 대상은 지급 후에도 남아 있어 구금 유지나 석방의 후속 결과를 선택한다.

목격한 손님은 벽/방향/층 조건에 따라 실제 출구로 달아나 신고한다. 직원은 진행 주문을 마친 뒤 문으로 가 경비를 부른다. 경비는 신고 15초 후 출입구에서 접수대로 걷고, 조사 허용 또는 응답 시간 초과 시 계단을 통해 지하 입구 주변을 제한 수색한다. 깊은 지하 전체를 아는 AI가 아니다. 발견하면 20닢 벌금과 구금 해제, 한 건 신고는 12닢 뇌물로 방문을 종료할 수 있다. 여러 신고면 뇌물을 거절한다.

## 검증
시뮬레이션 107개, 뷰포트/실제 입력 20개. 운영 회귀, 작업 취소, 기절/회복, 중복 운반 방지, 계단 이동, JSON 저장, 위치별 설치, 유지비/탈출, 의뢰 정산/보호/거절/실패, 목격 가림과 층 분리, 신고 시점, 직원 출입구 이동, 경비 방문/뇌물/수색/적발/벌금/깊은 공간 은폐를 검증한다.

경계 기억만으로 직원이 끝없이 소음 확인을 반복하던 조건을 수정했다. 새로 들리는 소리가 있어야 다시 접근한다.

## 실제 화면
v05-operation.png는 위층 제압·운반과 의뢰 상태, v05-prison.png는 지하 구금 및 조건 달성 상태다. Godot 명령을 사용하는 스크립트 시나리오를 실제 렌더링한 캡처다. 사용자 PC 플레이 완료와는 구분한다.
