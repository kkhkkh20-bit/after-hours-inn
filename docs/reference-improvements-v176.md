# 1.7.6 레퍼런스 조사와 적용 기획

## 확인한 공식 자료
- Prison Architect 개발사 변경 기록: 수감자 정보, 생활 일정, 필요 상태, 지능/보고 UI가 운영의 주요 구획으로 제시된다. 원작 전체 일정 편집기를 복제하지 않고 세 가지 관리 선택으로 축소한다. https://www.introversion.co.uk/prisonarchitect/builds
- Prison Architect 공식 Steam 개발 공지: 수감자를 정보원으로 영입하고 정보를 얻는 구조와 정보원 노출 위험이 설명된다. 우리는 신뢰·기분을 바탕으로 협력을 제안하고 주기적으로 정보를 얻는 자체 규칙을 쓴다. 원작 영입 조건이나 수치를 그대로 따르지 않는다. https://store.steampowered.com/news/posts/?appids=233450&enddate=1414673199&feed=steam_community_announcements
- Shadows of Doubt 개발자 DevBlog 4: 사건 자료와 정보 창을 코르크 게시판에서 정리하는 UI, 익숙한 창 조작과 설명을 강조한다. 우리는 복잡한 드래그 연결선 대신 조건 체크리스트와 정보 기록으로 정리한다. https://colepowered.com/shadows-of-doubt-devblog-4-case-folders-cork-boards/
- Tavern Master 개발사 소개: 직원 역할과 배치가 자동 운영을 좌우한다. 기존 접수·식사·청소 자동화는 유지하고 관리자가 일괄 대응할 수 있게 한다. https://untitledstudio.dev/games/tavern-master

## 이번 구현
1. 의뢰 게시판의 첫 버튼이 다음 단계가 된다. 수락 → 혐의 확인 → 생포 → 심문/자금 회수 → 정보 대조 → 보상으로 상황에 따라 바뀐다. 같은 창에서도 완료·대기·버튼 사용 가능 여부를 갱신한다.
2. 사건 조건 체크리스트와 최근 정보 기록을 보관한다. 원인·출처·신뢰성을 표시한다. 정보원 보고는 정보 재고가 되어 불확실한 진술을 대조하는 데 사용할 수 있다.
3. 감옥 전체 요약에서 수용 인원·배고픔·피로·기분·취약 보안을 찾고 해당 감옥으로 들어간다. 한 번에 식사·휴식·기본 경비를 복구하는 쉬운 관리도 둔다.
4. 감옥 생활 정책은 균형 자동 관리, 휴식 우선, 30초 임시 봉쇄 세 가지다. 수치와 실제 행동에 반영하고 봉쇄는 자동 해제한다.
5. 수감자를 돌보거나 차분히 심문하면 신뢰가 오른다. 신뢰·기분이 충분할 때 정보원으로 영입할 수 있다. 자동 보고는 주기가 있고 저장된다. 강압 심문은 신뢰를 떨어뜨린다.
6. 표적·정보원은 글자로 구분하고 메뉴의 첫 행동을 강조한다. 조작 영역을 새로 외부에 늘리지 않고 기존 인물·시설 선택창을 개선한다.

## 완료 범위와 제외
원작들의 구체적인 UI 배치를 전부 재현하거나 시스템 동등성을 주장하지 않는다. 정보원 보고는 허구의 거래·도주 단서이며 실시간 조직 AI나 독립된 경비 AI는 아니다. 모바일 실기기 조작감과 장시간 균형은 미확인이다.

## 반영 확인
변경 흐름을 포함한 집중 진단 101개를 통과했다. 실제 입력 이벤트를 통한 의뢰 보상 클릭, 열린 창 갱신, 정보원 보고 주기, 저장 복원, 정보 재고 사용, 빈 감옥 봉쇄 자동 해제를 포함한다. 모바일 실기기 검증은 하지 않았다. Prison Architect 자료는 과거 개발 기록이며 현재 버전의 정확한 규칙을 의미하지 않는다.
